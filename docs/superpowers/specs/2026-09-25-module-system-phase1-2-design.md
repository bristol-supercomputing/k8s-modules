# Kubernetes Module System — Phase 1 + 2 Design

Date: 2026-09-25
Parent design: [Kubernetes Module System — Design Plan](https://claude.ai/code/artifact/a487684a-c66e-44ae-a7d3-fca6f0f4c189)

This spec covers delivery phases 1 (prototype in kind) and 2 (controller and
validation) of the parent design. It keeps the parent's architecture: a
`Module` CRD, a controller that writes each module's flattened closure into
`status`, and static admission policies that run inside kube-apiserver. Where
this spec differs from the parent, the difference is called out under
[Changes from the parent design](#changes-from-the-parent-design).

## Scope

In scope:

- `Module` CRD (`modules.brics.ac.uk/v1alpha1`) with CRD-level CEL validation.
- Module controller: dependency resolution, ranks, conflict detection,
  `status.resolved`, conditions.
- A static MutatingAdmissionPolicy that injects image volumes, mounts, env and
  resolved annotations into pods.
- ValidatingAdmissionPolicies for pods (unknown modules, conflicts, access,
  immutability) and for `Module` objects (site guards, one default per family).
- Helm chart, kind dev environment, unit, envtest and kind e2e tests.

Out of scope for this cycle (later phases):

- The module NRI plugin: `LD_LIBRARY_PATH` prepend, host-module discovery,
  PVC binds, `maskPaths`, glibc check, per-node report.
- The Spack image pipeline.
- CXI DRA driver changes.
- Init and ephemeral containers. Only `spec.containers` receive mounts and env.

**Known limit on forgery:** admission rejects a `resolved.*` value whose
module is not of the key's family, and any value that differs from what an
existing Module it names would write. It cannot reject a value naming a Module
that does not exist (that needs cross-param reasoning). The phase-3 NRI plugin
must therefore re-check every annotation against the Module catalogue and never
act on an annotation alone.

**Known limit until phase 3:** `host` and `pvc` modules are resolved and
annotated, but nothing applies them at runtime. A pod that loads one is
admitted and starts without those libraries. Fail-closed behaviour arrives with
the NRI plugin.

## Changes from the parent design

1. **Annotations are keyed by family and use a flat string value, not JSON.**
   Kubernetes CEL can't decode JSON, so the parent's JSON values can't be
   checked at admission. Keying by family also makes a version conflict
   structural: two nccl versions write the same key.
2. **Conflict and access checks use a param fan-out VAP.** It compares each
   referenced Module's `status.resolved.annotations` with the pod by exact
   string equality. That single rule covers family conflicts, env conflicts
   across separate requests, forged values, and access through dependencies.
3. **Tampering is narrowed, not eliminated.** A user can write annotations for
   a module they are allowed to load and that is consistent with everything
   else in the pod. That is equivalent to loading it. They cannot forge a
   value, bypass access or break consistency (with one gap, a value naming a
   Module that does not exist; see the known limit on forgery under Scope). A strict "only what `load`
   implies" rule needs cross-param reasoning that CEL cannot do.
4. **Volume names are sanitised.** Pod volume names must be DNS labels, so
   `mod-nccl-2.29.2` becomes `mod-nccl-2-29-2-a6b4217c` (a hash suffix keeps
   sanitised names unique).
5. **`spec.mountPath` is removed.** A module is always mounted at
   `/opt/modules/<family>/<version>`. Separate families can then never
   overlap, so no overlap check is needed.
6. **`metadata.name` must equal `<family>-<version>`**, enforced by the CRD.
   Host modules use a version such as `host` (`libfabric-host`).
7. **`source.pvc` is applied by the NRI plugin (phase 3), like `host`.** The
   PVC lives in the module-system namespace and is mounted by the NRI
   DaemonSet. The plugin bind-mounts `<pvc mount>/<subPath>` read-only at the
   module's mount path. User pods never reference the PVC.
8. **Access uses `matchLabels` only** in v1alpha1. Evaluating full
   LabelSelectors in CEL is error-prone. Open question 4 stays open.
9. **`dependsOn` names exact modules only**, never family defaults, so a
   closure never changes when a default label moves.
10. **Pod UPDATE may not change module annotations.** Without this, a user
    could edit annotations after admission.

## Module API

Cluster-scoped, group `modules.brics.ac.uk`, version `v1alpha1`, kind `Module`.

```yaml
apiVersion: modules.brics.ac.uk/v1alpha1
kind: Module
metadata:
  name: aws-ofi-nccl-1.18.0
  labels:
    modules.brics.ac.uk/family: aws-ofi-nccl   # informational
    modules.brics.ac.uk/default: "true"        # optional, one per family
spec:
  family: aws-ofi-nccl
  version: 1.18.0
  source:                     # exactly one of image | host | pvc
    image:
      reference: registry.isambard/modules/aws-ofi-nccl@sha256:<64 hex>
    # host: {discover: {roots: [libfabric.so.1, libcxi.so.1]}}
    # pvc:  {claimName: spack-apps, subPath: nccl/2.29.2}
  dependsOn: [nccl-2.29.2, libfabric-host]
  env:
    prependPath:
      LD_LIBRARY_PATH: [lib]  # relative to the mount path
    set:
      NCCL_NET: "AWS Libfabric"
  maskPaths: []               # absolute container paths; applied in phase 3
  access:
    matchLabels: {}           # namespace labels; empty or absent = every namespace
status:
  resolved: { ... }           # see Resolved status
  conditions: [ ... ]
```

### CRD validation (fixed rules, CEL in the CRD)

- `spec` is immutable: `self == oldSelf`.
- `metadata.name == spec.family + '-' + spec.version`.
- `family` matches `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$` and is at most 40 characters.
- `version` matches `^[A-Za-z0-9]([A-Za-z0-9._-]*[A-Za-z0-9])?$` and is at most 20 characters.
- Exactly one of `source.image`, `source.host` and `source.pvc` is set.
- `source.image.reference` ends in `@sha256:<64 lowercase hex>`.
- `source.host.discover.roots` is non-empty, and each root is a soname
  (`^lib[A-Za-z0-9_.+-]+\.so(\.[0-9]+)*$`, no `/`).
- `source.pvc.subPath` is relative, has no `..` segments, and `claimName` is a
  DNS subdomain.
- `env.prependPath` keys are limited to `LD_LIBRARY_PATH`. Entries are
  relative, with no `..` segments.
- `env.set` names match `^[A-Za-z][A-Za-z0-9_]*[A-Za-z0-9]$`, are at most 63
  characters, and are not `LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT` or `PATH`.
- `dependsOn` entries are valid Module names, with at most 32 entries, and
  must not include the module itself.
- `maskPaths` entries are absolute.

### Site guards (Helm-configured VAP on Module CREATE and UPDATE)

- `source.image.reference` starts with one of `values.registryAllowlist`.
  Default: `registry.isambard/modules/`.
- Every `env.set` name starts with one of `values.envPrefixAllowlist`.
  Default: `NCCL_`, `FI_`, `CXIP_`, `UCX_`, `OMPI_`.
- A Module with the default label is rejected if another Module of the same
  family already carries it. This is a param fan-out over Modules. Labels are
  mutable, so it also runs on UPDATE.

## Resolution (`internal/resolve`)

```go
func Resolve(name string, catalogue map[string]*v1alpha1.Module) (*v1alpha1.Resolved, error)
```

It is pure and deterministic, and runs over whatever Modules the cache holds.

1. Walk `dependsOn` depth-first from `name`.
   - A missing name returns `ErrDependencyNotFound{Module, Missing}`.
   - A cycle returns `ErrDependencyCycle{Path}`, for example `[a, b, a]`.
2. **Family conflict:** two closure members share a family →
   `ErrFamilyConflict{Family, Modules}`.
3. **Env conflict:** two closure members set the same `env.set` name to
   different values → `ErrEnvConflict{Name, Modules, Values}`.
4. **Rank:** a leaf gets 10. Any other module gets `10 × (1 + max(dependency rank / 10))`.
   A module therefore always ranks above everything it depends on.
5. Output lists are sorted by (rank, name), so output is stable.

`Resolve` does not check PVCs. The controller does that (see Controller).

### Resolved status

```yaml
status:
  resolved:
    modules: [nccl-2.29.2, libfabric-host, aws-ofi-nccl-1.18.0]    # sorted by (rank, name)
    volumes:                 # image sources only
    - name: mod-nccl-2-29-2-a6b4217c
      reference: registry.isambard/modules/nccl@sha256:...
    mounts:                  # image sources only
    - name: mod-nccl-2-29-2-a6b4217c
      mountPath: /opt/modules/nccl/2.29.2
    env:                     # union of env.set across the closure, sorted by name
    - {name: NCCL_NET, value: "AWS Libfabric"}
    annotations:             # the exact entries the pod must carry
      resolved.modules.brics.ac.uk/nccl: "nccl-2.29.2;rank=10;src=image;mount=/opt/modules/nccl/2.29.2;lib=/opt/modules/nccl/2.29.2/lib"
      resolved.modules.brics.ac.uk/libfabric: "libfabric-host;rank=10;src=host;mount=/opt/modules/libfabric/host;lib=/opt/modules/libfabric/host/lib"
      resolved.modules.brics.ac.uk/aws-ofi-nccl: "aws-ofi-nccl-1.18.0;rank=20;src=image;mount=/opt/modules/aws-ofi-nccl/1.18.0;lib=/opt/modules/aws-ofi-nccl/1.18.0/lib"
      env.modules.brics.ac.uk/NCCL_NET: "AWS Libfabric"
```

**Volume name:** `mod-` + the module name, lowercased, with every character
outside `[a-z0-9-]` replaced by `-`. If that changed the name, or the result is
longer than 63 characters, it is cut to at most 54 characters and given `-` +
the first 8 hex characters of the name's SHA-256. Sanitising alone is lossy
(`nccl-2.29.2` and `nccl-2-29.2` would share `mod-nccl-2-29-2`), so e.g.
`nccl-2.29.2` becomes `mod-nccl-2-29-2-a6b4217c`.

**Resolved annotation value.** The fields appear in this fixed order, separated
by `;`. Optional fields are omitted when empty.

| Field | Form | Notes |
|---|---|---|
| name | `<module name>` | Always first. CEL matches with `startsWith(name + ';')`. |
| rank | `rank=<int>` | |
| src | `src=image` \| `src=host` \| `src=pvc:<claimName>/<subPath>` | |
| mount | `mount=<abs path>` | Always `/opt/modules/<family>/<version>`. |
| lib | `lib=<abs>[:<abs>...]` | From `prependPath.LD_LIBRARY_PATH`, in spec order. |
| mask | `mask=<abs>[:<abs>...]` | From `maskPaths`. |

For a `host` module, `lib` is always `<mount>/lib`, whatever `prependPath`
says, because the NRI plugin places the roots there. That keeps the value
fixed before any discovery happens.

The value may not contain `;` inside a field. The CRD rules above already
guarantee this.

**Env annotation:** the key is `env.modules.brics.ac.uk/<NAME>` and the value is
the literal value. Admission uses these annotations only for conflict
detection. The container env itself is injected from `status.resolved.env`.

## Controller (`internal/controller`)

- One reconciler for `Module`. A watch on Modules maps any event to "enqueue
  every Module". The catalogue is small, and a create or delete can change any
  closure.
- Reconcile(name):
  1. Build the catalogue from the informer cache.
  2. Call `resolve.Resolve`.
  3. For a `pvc` source anywhere in the closure, check that the PVC exists in
     `--modules-namespace` and has the `ReadOnlyMany` access mode.
  4. On success, set `status.resolved`, `Resolved=True/Resolved` and
     `ConflictFree=True/NoConflicts`.
  5. On failure, clear `status.resolved` and set the conditions below.

| Failure | Resolved | ConflictFree |
|---|---|---|
| Dependency not found | False / `DependencyNotFound` | Unknown |
| Cycle | False / `DependencyCycle` | Unknown |
| Family conflict | False / `Conflict` | False / `FamilyConflict` |
| Env conflict | False / `Conflict` | False / `EnvConflict` |
| PVC missing or not ReadOnlyMany | False / `PVCInvalid` | Unknown |

  Condition messages name the modules, family, variable or PVC involved. Every
  condition carries `observedGeneration`.
- The status is patched only when it differs, so reconciles don't loop.
- RBAC: `get/list/watch` on `modules`, `update/patch` on `modules/status`, and
  `get/list/watch` on `persistentvolumeclaims` in the modules namespace only
  (Role). The controller has no access to admission policies or pods.
- Flags: `--modules-namespace`, leader election (on by default), metrics and
  health probe addresses.

## Admission policies

All policies ship in the Helm chart, are managed by one release, and use
`failurePolicy: Fail`.

### 1. MutatingAdmissionPolicy `modules.brics.ac.uk`

This is the policy from the parent design, with these differences:

- `paramKind: Module`. The binding uses `paramRef: {selector: {}, parameterNotFoundAction: Allow}`.
- It matches pods on CREATE.
- The `requested` variable splits `modules.brics.ac.uk/load` on `,` and trims
  each entry.
- `matchConditions`:
  - `has(params.status.resolved)`
  - The pod requested this module: `params.metadata.name in requested`, or the
    family is requested and this Module has the default label.
  - The namespace is allowed: `params.spec.access.matchLabels` is absent or
    empty, or every key/value in it is present in `namespaceObject.metadata.labels`.
- The ApplyConfiguration mutation sets:
  - `metadata.annotations` = `params.status.resolved.annotations`
  - `spec.volumes` = one image volume per `resolved.volumes` entry, with `pullPolicy: IfNotPresent`
  - for each container, `volumeMounts` = `resolved.mounts` (read-only)
  - for each container, `env` = `resolved.env` minus any name already in that container's env (user env wins)
- `reinvocationPolicy: IfNeeded`. Evaluations are idempotent, and a diamond
  produces identical entries that merge by key.

### 2. ValidatingAdmissionPolicy `pods.modules.brics.ac.uk` (no params)

It matches pods on CREATE and UPDATE.

- **CREATE, syntax:** each `load` entry is a valid Module name or family name,
  and there are at most 32 entries.
- **CREATE, unknown:** each `load` entry `r` is satisfied: either some
  `resolved.modules.brics.ac.uk/*` annotation value starts with `r + ';'`, or
  the key `resolved.modules.brics.ac.uk/<r>` exists (a family default). The
  message: `module "<r>" was not loaded: not found, not resolved, or not
  permitted in namespace "<ns>" (kubectl get module <r>)`.
- **CREATE, family keys:** every `resolved.modules.brics.ac.uk/<f>` value
  starts with `<f>-`, so the value names a module of that family and the
  consistency policy compares it.
- **UPDATE** (including `pods/status`, which can also write annotations): the `modules.brics.ac.uk/load` annotation and every
  `resolved.modules.brics.ac.uk/*` and `env.modules.brics.ac.uk/*` annotation
  are unchanged from `oldObject`.

### 3. ValidatingAdmissionPolicy `pod-consistency.modules.brics.ac.uk` (param fan-out)

`paramKind: Module`, `selector: {}`, `parameterNotFoundAction: Allow`. It
matches pods on CREATE.

The pod **references** Module P if P's name is in `load`, or P's family is in
`load` and P has the default label, or the annotation
`resolved.modules.brics.ac.uk/<P.family>` starts with `P.name + ';'`.

For each referenced P:

- **Unresolved:** if P is requested but has no `status.resolved`, the pod is
  rejected with P's `Resolved` condition message.
- **Access:** P's `access.matchLabels` must match the namespace. Otherwise:
  `module "<P>" is not permitted in namespace "<ns>"`.
- **Consistency:** every entry in `P.status.resolved.annotations` must be
  present in the pod with the identical value. Otherwise:
  `module "<P>" requires <key>=<expected>, but the pod has <actual>`. This
  message covers:
  - family conflicts (another nccl version won the key)
  - env conflicts (another module's value won `env.*/<NAME>`)
  - forged values

### 4. ValidatingAdmissionPolicy `module-guards.modules.brics.ac.uk`

This policy implements the site guards above: the registry allowlist and env
prefix allowlist (no params), plus a param fan-out binding for the one-default
rule. It matches `modules` on CREATE and UPDATE.

## Testing

**Unit (`internal/resolve`), table-driven:**
- single module
- chain
- diamond (the shared dependency appears once)
- missing dependency
- self and indirect cycles
- family conflict
- env conflict and env agreement
- rank ordering
- volume-name sanitising, including the truncation and hash
- canonical annotation values, including host and pvc forms

**envtest (kube-apiserver 1.36 via setup-envtest):**
- **CRD rules:** spec immutability, name = family-version, digest pattern,
  one source kind, soname roots, forbidden env names, prependPath keys.
- **Controller:**
  - resolves a chain
  - a dependent becomes resolved when a missing dependency is created later
  - deleting a dependency makes its dependents unresolved
  - conflict conditions
  - PVC checks
- **Admission policies** (`helm template` output applied to envtest, then
  pods created; no nodes needed):
  - single load injects the volume, mount, env and annotations
  - a diamond merges cleanly
  - a user-set env var wins
  - family conflict across requests is rejected
  - env conflict across requests is rejected
  - a forged annotation value is rejected
  - access denial is rejected
  - an unknown module is rejected
  - an unresolved module is rejected with its reason
  - a family-default load works
  - UPDATE changing annotations is rejected
  - the Module registry allowlist is enforced
  - the one-default-per-family rule is enforced

**kind e2e (`go test -tags e2e ./test/e2e`):**
- A pod with `modules.brics.ac.uk/load: nccl-2.29.2` runs. Inside the
  container, `/opt/modules/nccl/2.29.2/lib/libnccl.so.2` exists and the
  module's env var is set.
- Diamond, conflict and cycle scenarios behave the same as in envtest.

- **Phase 1:** on kind v1.36.4, the chart installs, MutatingAdmissionPolicy v1

- **Phase 2:** all unit and envtest tests pass, plus the kind diamond,

## Open questions carried forward

From the parent design: 1 (Isambard k8s and containerd versions), 2 (image
volume size and pull time), 3 (`libgdrapi` placement), 4 (namespace access
model), 6 (`PATH` entries), 7 (upstream appetite). Question 5 is resolved: this
is a new repository.

New questions, to settle in the phase 3 spec:

- The NRI DaemonSet's volume list is static, so every `pvc` claim must be
  listed in Helm values before its Module can be used. Should the controller
  report "claim not mounted by the NRI DaemonSet" as a condition?
- NRI mount adjustments take host paths. The plugin must find its own PVC
  volume's kubelet path (for example from `/proc/self/mountinfo`).
- Should init containers receive modules?
